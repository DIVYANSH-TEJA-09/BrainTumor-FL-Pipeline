PART 2: WHAT'S BROKEN — MUST FIX
================================================================================

ISSUE #1: FABRICATED TIMESTAMPS (CRITICAL — EVERYTHING DEPENDS ON THIS)
-------------------------------------------------------------------------
Location: Cell 6, line: days_from_baseline = i * 90

You assumed every scan is exactly 90 days apart. This is not real data — the
MU-Glioma-Post dataset has irregular scan intervals. The actual dates are
available in the DICOM metadata (StudyDate field) or in the dataset's clinical
spreadsheet.

Why this breaks everything:
  - Growth rate k is defined PER UNIT TIME. If time is wrong, k is wrong.
  - A tumor growing 10 cm³ over 30 days vs 365 days has completely different
    clinical significance, but your code treats them identically.
  - Doubling times you report are fiction.
  - RANO classifications are unreliable.
  - The tumor_volumes.csv you generated is unreliable for any downstream use.

FIX: Extract real acquisition dates from DICOM headers or the dataset's
metadata CSV. Replace i * 90 with actual (scan_date - baseline_date).days.
Then re-run the entire pipeline.


ISSUE #2: NO VALIDATION — ZERO EVIDENCE OF PREDICTIVE ACCURACY
---------------------------------------------------------------
You report R² scores, but these are computed on the TRAINING data (the same
points the model was fitted to). This tells us nothing about whether the model
can actually predict future volumes.

Key problem: Many patients show R² = 1.0. This is because you're fitting
2-parameter models (linear, exponential) to exactly 2 data points. A line
through 2 points is always perfect — R² = 1.0 is guaranteed. This is not
accuracy; it's a mathematical tautology.

Your growth predictions and RANO classifications are completely unvalidated.

FIX: Implement temporal holdout validation:
  - For patients with 3+ timepoints, fit on the first N-1 timepoints
  - Predict the last timepoint
  - Compare prediction vs actual
  - Report MAE, MAPE, and direction accuracy (did you correctly predict
    growth vs shrinkage?) on this held-out data

ISSUE #5: FAKE UNCERTAINTY BANDS
----------------------------------
Location: Cell 11, lines with * 0.9 and * 1.1

Your "uncertainty" is just a hardcoded ±10% ribbon. It doesn't change based
on model confidence, prediction horizon, or data quality. This is cosmetic,
not statistical.

FIX: Use the covariance matrix from curve_fit to compute real parameter
uncertainty, or use bootstrap resampling to generate proper confidence
intervals.


ISSUE #6: MODEL SELECTION OVERFITS
------------------------------------
You select the best model purely by R². Complex models (3 parameters) will
almost always beat simple ones (2 parameters) on training data even when
the simpler model better represents reality.

FIX: Use AIC (Akaike Information Criterion) or BIC (Bayesian Information
Criterion) which penalize model complexity. At minimum, prefer simpler
models when R² difference is < 0.05.


ISSUE #7: POWER LAW MODEL IS DEAD CODE
----------------------------------------
You defined power_law() in Cell 7 but never call it in fit_all_models_for_
patient() or include it in the model_funcs dictionary. Either use it or
remove it.


ISSUE #8: MISSING METRICS
---------------------------
The guide specifies VDE (Velocity of Diametric Expansion) as a key metric.
You didn't implement it. Formula: D_effective = (6V/π)^(1/3), then
VDE = (D2 - D1) / delta_t in mm/month.

Also missing: half-life reporting for shrinking tumors (exponential k < 0).
Reporting "the tumor halves every X days" is clinically meaningful.
